# Проверка дизайн-комплекта

7 сентября 2026 · результат: комплект готов к дизайн-ревью. Проверка относится к автономным макетам, а не к работе production API или итоговому соответствию WCAG.


## Редакция 02 — правки пользователя

Проверены все четыре правки: солнце/луна, бургер на телефоне и планшете, отдельный завершённый звонок с транскриптами и фидбеком, единый футер лендинга на каждом продуктовом экране. В 132 базовых сочетаниях подтверждены один футер и одинаковый набор из семи ссылок. Видимый переключатель темы везде имеет иконку без текста и область 44×44 px; бургер — 44×44 px на ширинах менее 1024 px.

`qa-revision-02.json`: 13 дополнительных проверок пройдены. Проверены открытие меню и замена на X, Escape с возвратом фокуса, клик снаружи, совместимость старой ссылки call/completed, переключение транскриптов, обязательная оценка результата, ограничение оценки качества до готовности финального транскрипта, счётчик комментария, сохранение формы при смене темы, подтверждение отправки, навигация атласа и галерея. Фидбек в макете остаётся демонстрационным.

Визуально просмотрены завершённый звонок в обеих темах, мобильная форма качества, открытое планшетное меню админки и нижние части звонка/админки с футером. Сравнение до/после в одном входе: `revisions/02/before-completed-desktop-light.png` и `screens/call-completed-desktop-light.png`, 1440×1024 CSS px. Сохранены шрифт, палитра, логотип и двухколоночная структура. Изменены согласованные элементы: иконка темы, переключение транскриптов, положение фидбека. Отдельные свидетельства находятся в `revisions/02/`.

При проверке выявлено смешивание старых и новых ресурсов браузерного кэша. Добавлена версия URL для CSS/JS, затем заново пройдены все 33 экрана и 162 состояния. Ошибка загрузки новой функции разрешения экранов устранена. Короткие сообщения системных состояний проверены как непустые; их малая длина сама по себе не является дефектом.

## 2. Исправления по результатам проверки

Плотность dashboard: первая версия формы скрывала Call options под закреплённым footer. Для desktop уменьшены интервалы между группами, поля приведены к 44 px, счётчик помещён внутрь textarea 112 px. При повторной проверке 1300×960 низ Call options — 882 px, верх footer — 883 px. Контрол полностью доступен; на меньших высотах страница естественно прокручивается.

Длинные немецкие заголовки: Privacy и Terms сначала имели пустые исходные snapshots. Они восстановлены из seed-content.ts с явной записью происхождения. После заполнения проявилось переполнение на 320 px; добавлены hyphens и overflow-wrap. Повторная проверка показывает scrollWidth = viewportWidth для обоих документов.

Mobile admin: фильтры списка звонков изначально свёрнуты, повторная навигация в начале main убрана, записи таблиц получили подписи. Навигация аккаунта переносится на следующую строку. Условные поля delivery/fallback/reason скрыты до соответствующего выбора. Язык EN/DE не предлагается в фиксированной английской админке.

Редактор landing: раскрытия для восьми дополнительных блоков получили поля своих существующих типов, вместо общего текстового заполнителя. Лимиты и типы перечислены в PAGE-SPECS.md. Опасные действия пользователя и публикация требуют заполнения причины перед открытием демонстрационного подтверждения.

## 3. Визуальная сверка

Источник: утверждённые `assets/approved-light.png`, `assets/approved-dark.png` (исходные доски 1640×959). Реализация: `screens/new-call-comparison-light.png` и `screens/new-call-comparison-dark.png`, снятые при 1300×960 CSS px; browser output 1285×949. `comparison.html` объединяет source/target в одном сравнении, `screens/qa-comparison.png` сохраняет его вид.

Проверены типографическая иерархия, ритм формы, пропорция истории и рабочей области, обе палитры, исходный векторный wordmark и маленький зелёный портал. Отдельно визуально просмотрены desktop landing/register, mobile review/account/admin calls и desktop admin content. Макеты сохраняют общую открытую композицию без добавления декоративных иллюстраций или чужого логотипа.

Допустимые отличия от ImageGen-основы: реальные native controls и их контраст; согласованные иконки Heroicons для темы и меню; синтетические получатели; перенос статуса истории на вторую строку; уточнённые ограничения и helper copy из репозитория. Растровая доска не задаёт точное семейство шрифта: использован существующий Geist. Финальные значения задают tokens/styles/GUIDELINES, а не измерение размытого пикселя доски.

## 4. Границы результата

Не проверялись реальные SMS, телефония, запись/аудио, API-публикация, выдача кредитов, удаление данных и серверные роли. Экспорт и проигрыватель иллюстрируют действия. Вспомогательные кнопки редакторов/операционных консолей могут показывать пояснение вместо сохранения данных; смена состояния сбрасывает пример. Это ожидаемая граница дизайн-атласа.

DE-варианты основных клиентских сценариев и все шесть документов присутствуют, но отдельные технические значения/option labels остаются EN. Полная интеграция существующих i18n-ключей, проверки screen reader, реального zoom/мобильной клавиатуры и всех backend-кодов ошибок относятся к следующему этапу. Новые страницы ещё требуют пользовательского утверждения.

В журнале in-app browser за длительный прогон встречались три сообщения MutationObserver.observe без указания исходного файла. Код атласа не содержит MutationObserver; источник этих сообщений не установлен. Они не сопровождались пустыми экранами или отказом проверенных переходов. Поэтому здесь не заявляется полностью чистый browser console.

Приложение не переносилось на этот дизайн; все созданные материалы находятся в Design. Рабочие источники с данными локального аккаунта не входят в галерею и переносимый архив.
