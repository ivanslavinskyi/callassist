# Упрощение Live: реализация 28 сентября 2026

Три пункта [согласованного плана](live-simplification-implementation-plan-2026-09-28.md) реализованы в рабочей копии и применены к локальному API перезапуском 28 сентября в 17:56 CEST (Europe/Zurich). Миграции БД, новые каналы доставки и отдельная система управления разговорными ходами не добавлялись. Production не обновлялся.

## Что изменено

1. **Завершение.** Принятый `end_call` проходит обычный цикл результата инструмента и продолжения Responses. Приложение больше не отправляет конкурирующее `Finish naturally now`. Завершение соответствующего backend-продолжения разрешает проверку речи, но не подменяет подтверждение проигрывания. Проверка оценивает законченность разговора, а не бизнес-достоверность уже произнесённых слов. При продолжающемся разговоре управление возвращается Live; при неопределённости, ошибке или отсутствии продолжения используется одно короткое локализованное прощание. Для него нет дополнительного сетевого классификатора. Сохранены ограничения времени, один запрос проверки одновременно, максимум две попытки, отмена при перебивании и проверка актуального playback mark. Устаревшая backend-ошибка или таймер не могут оборвать возобновлённый разговор.

2. **Контекст и настройки.** Live и backend получают согласованный утверждённый контекст: вопросы с обязательностью и назначением, условия продолжения, критерии результата/остановки, факты, ограничения, полномочия встречи и реальные возможности хранения. Thinking appends состоят из самостоятельных фрагментов полей до 450 UTF-8 байт; JSON больше не разрезается произвольно. Естественные acknowledgments разрешены; обещание дальнейшего действия требует известного исполнителя, полномочия и возможности. Результат внешнего действия подтверждается по ответу инструмента. `resultHandling` и отдельная доставка убраны из формы. Тон и обращение доступны только superadmin; новые defaults для всех — neutral/formal. Сервер применяет политику до fingerprint. Старые delivery instructions переходят в видимый контекст без обрезания; изменённый повтор проходит существующую перекомпиляцию и review. Старые утверждения и hashes не переписываются.

3. **Вступление.** Обычный purpose/readiness формулирует Live после согласия и запуска записи. Непустой assistance disclosure по-прежнему произносится отдельно один раз. Вопрос об удобстве задаётся по смыслу; уже полученное приглашение продолжить или ответ по задаче не требует повторного опроса. В review вступление обозначено как пример. Компилятор версии 6 сохраняет имя инициатора в справочном контексте без обязательного повторного представления; версии 3–5 остаются читаемыми.

Во время реального синтетического прогона обнаружено дополнительное противоречие прежней controlled-speech инструкции: после обязательной реплики она предлагала ждать следующую команду приложения. Live распознал русское согласие, но не делегировал его. Инструкция теперь явно сохраняет действующую delegation policy во время молчаливого ожидания. Сам механизм согласия не заменялся и новый классификатор согласия не добавлялся. Последующие русский и немецкий прогоны приняли голосовое согласие.

## Проверки

- Общий workspace-прогон: contracts — 142/142; web — 320/320; API — 1401/1408 на первом полном прогоне. Семь несовпадений относились к старым fixture-ожиданиям версии, тона и расположения имени. Они исправлены; повтор семи затронутых наборов — 186/186. В полном прогоне прошли PostgreSQL-интеграции, включая 20 проверок повторного звонка и сохранности исходных компиляций.
- После финальных изменений таймеров/инструкций: четыре voice-набора — 123/123; три затронутых web-набора — 12/12. Проверяются backend continuation, разные решения closing check, единственный fallback, обязательный mark, перебивания, старые результаты и таймеры, исходящие полномочия, native opening и немедленный ответ. Роли проверены на сервере и в отрисованной форме.
- `pnpm lint`, `pnpm typecheck`, `pnpm build` выполнены для всех пакетов. Общий тестовый прогон использует отдельную временную PostgreSQL-базу; данные рабочих звонков не менялись.
- Настоящие Live/Responses с синтетическим собеседником и имитацией Twilio: русский и немецкий информационные сценарии прошли consent → recording → native opening → ответ → end_call → подтверждённое проигрывание → hangup. По одной closing-проверке, без fallback. От принятия end_call до имитируемого hangup: 7,8 с и 9,8 с соответственно; это полное время завершения со speech/backend/playback, **не длительность тишины**. Проверка модели занимала около 1,5 с и 1,3 с. Инициатор не представлялся повторно; обещаний отправить/передать результат не было.
- Реальный text-only probe классификатора: 14/14, включая прощания на всех семи call locales, незаконченный acknowledgment, продолжающий вопрос и прежнюю проблемную фразу «передам дальше». Последняя теперь признаётся завершённой репликой; её допустимость по задаче регулируется инструкциями говорящей модели, а не проверкой уже произнесённой реплики.

Локальные журналы: `.tools/live-simplification-full-suite.log`, `live-simplification-final-focused.log`, `live-simplification-final-voice.log`, `live-simplification-final-web.log`, `live-simplification-{lint,typecheck,build}.log`, `live-simplification-real-{ru,de,semantics}.log`. Синтетические аудио и transcript-результаты находятся в игнорируемом `.tools/live-simplification-audio/`; клиентских записей там нет.

## Границы приёмки

Локальный API перезапущен по запросу владельца после проверки отсутствия активных звонков: `active=0`, 87 миграций до `0086_live_voice_telemetry.sql`. Новый процесс обслуживает порты 4000/4001; `/health/live` возвращает `alive`, `/health/ready` — `ready`, база — `ready`. Сохранены текущий туннель и режим embedded worker. Профиль тестирования: `VOICE_RUNTIME_DRIVER=live`, fallback=false, `gpt-live-1`, delegation=`gpt-6-luna`, agent hangup=true. Интерфейс доступен по адресу [localhost:3000/ru](http://localhost:3000/ru). Для проверки новых настроек и компилятора 6 создать новый план либо отредактировать старый и заново проверить/утвердить его; исторические утверждения не переписываются. Порядок проверки — в local-testing.md (local operational document; excluded from Git).

Проверки переходов с моками не доказывают естественность речи модели. Реальные синтетические прогоны подтверждают конкретные информационные сценарии; полная разговорная матрица из плана, прослушивание на телефоне и визуальная проверка узкого экрана остаются открытыми. В немецком прогоне прозвучало короткое «einen Moment bitte»; запрета всех подобных фраз нет. После прогонов инструкции дополнительно уточнены: попрощаться один раз и не вставлять содержательный вопрос в purpose до проверки удобства. Эти уточнения не выдаются за отдельно измеренный новый телефонный прогон.

Надёжность действий и проигрывания обеспечивают сохранённые проверки приложения. Достоверность свободных формулировок зависит от Live и не является детерминированной гарантией отсутствия любых выдуманных реплик. Локальный перезапуск применил изменения к новым голосовым сессиям; успешная готовность API не заменяет разговорную приёмку. Реальных исходящих вызовов в рамках этой реализации и перезапуска не делалось.
