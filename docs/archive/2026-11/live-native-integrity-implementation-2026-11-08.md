# Native GPT-Live: реализация проверки целостности

Дата: 8 ноября 2026. Ветка: `codex/live-audit-validation-2026-11-05`.

Реализованы программные изменения из [аудита W0–W7](live-native-integrity-audit-plan-2026-11-08.md). Этот документ описывает итоговую реализацию; исходный аудит сохраняет состояние до изменений. Новая версия предназначена для локальных тестов. Акустическая приёмка и решение о публичной beta остаются отдельными этапами.

## 1. Архитектура и версии

Live получает исходное задание, контекст, факты, уточнения и утверждённые полномочия со старта. Модель самостоятельно ведёт вступление, спрашивает об удобстве разговора, выясняет неизвестные условия, выбирает нужную ветвь, отвечает и кратко завершает разговор от имени представляемого лица. Приложение проверяет полномочия и доказательства на границах действий, сохраняет результат и обеспечивает отключение после прощания. Дополнительного разрешения backend на каждую реплику нет.

| Слой | Новая версия / поведение |
| --- | --- |
| Preparation policy | `preparation-live-native-integrity-2026-11-08` |
| Compiler | `brief-compiler-13` |
| План / подтверждение | schema 9 / snapshot 8 |
| Native runtime | `live-native-integrity-2026-11-08` |
| Новая оценка | `summary-v8`, evidence format `native-summary-v3` |
| Архив телеметрии | Корневые manifest/schema v4; существующие JSONL v2/v3 сохранены |
| Диагностика тестов | Отдельные project/key, experiment ID и локальный журнал бюджета |

Модели, тарифы, голос, алгоритм обычных ответов и таймеры завершения не менялись. Сохранены progressive-инструкции: сначала неизвестное условие, затем зависимое действие; ограничения раскрываются по необходимости, полная логика задания не зачитывается. Общий профиль не получает appointment-инструменты. Профили book/confirm_existing/reschedule/cancel выбираются по утверждённым полномочиям.

Основные факты остаются в начальном контексте. Полное содержимое необязательных справочных разделов находится отдельно от `snapshot.plan`; со старта доступен индекс, раздел запрашивается через `get_task_context`. Сохранены лимиты ввода и provider admission до набора. Полномочия и условия не обрезаются молча.

## 2. W1 — понятные ошибки подготовки

Добавлен необязательный типизированный `issue`: вид причины, код, известный источник/категории, следующий шаг, возможность повтора и затронутые поля. Он доступен в policy decision и ответах подготовки, включая повторное получение по idempotency key. Для этого не понадобилась новая миграция.

Пользователь получает объяснение на выбранном языке интерфейса: ограничение политики, неподдерживаемая возможность, недостающая информация, неверный ввод, временная недоступность, очередь/бюджет, ошибка проверки сгенерированного плана, ожидание или отмена. Поддержаны de/fr/it/rm/en/ru/uk.

Известные причины модерации сохраняются. Если провайдер отказал без конкретной категории, приложение не придумывает её. Отказ выходной модерации описывается как проблема с подготовленным планом, а не как обвинение пользователя. В обычный UI не выводятся сырые ошибки провайдера, системные промты или секреты. Для старых данных без причины предусмотрено общее объяснение.

Поле необязательное, без значения по умолчанию: старые compilation hashes и подтверждения сохраняют прежнее значение. Старые policy versions продолжают компилироваться своими версиями; новый compiler выбирается только новой политикой.

Основные файлы: `packages/contracts/src/preparation-issue.ts`, `apps/api/src/brief-compiler/brief-compiler.ts`, `apps/api/src/call-service.ts`, `apps/web/components/compilation-review.tsx`, `apps/web/lib/i18n/preparation-issue-messages.ts`.

## 3. W2 — числовые условия действия

На границе `prepare_appointment` приложение связывает предложенную сумму/валюту и необходимую длительность с буквальной цитатой собеседника. Подстановка моделью 90 при фактически произнесённых 150 больше не проходит только потому, что обе суммы правдоподобны. Утверждённый потолок цены и календарные ограничения проверяются отдельно.

Проверка различает фиксированную сумму, диапазон/цену «от», почасовую цену, доплаты, отрицание, бесплатную услугу и отсутствие предоплаты. Бесплатная оценка не считается бесплатной услугой. Для явно бесплатной услуги валюта не выдумывается. Поддержаны распространённые цифровые формы, десятичные и тысячные разделители, числительные в EN/DE/FR/IT/RU/UK и распространённые обозначения CHF/EUR/USD/GBP. Длительность может подтверждаться минутами/часами либо явно названным временем окончания того же дня; переход через полночь не предполагается.

В журнал сохраняется host-created receipt: точная цитата, позиции, хеш наблюдавшегося текста, проверенная сумма/валюта или бесплатность, проверенная длительность. При подтверждении результата и завершении проверяются последующие числовые коррекции. Противоречие переводит действие в uncertain. Повторная доставка результата остаётся идемпотентной. После восстановления сохранённая проверенная цитата может быть использована без повторного вопроса, но не скрывает новые коррекции.

Это консервативная проверка известных форм, а не универсальное понимание любого выражения цены. Неподдержанная или неоднозначная формулировка не даёт разрешения. Смысл услуги, условий и ветвей продолжает интерпретировать backend по исходным словам; receipt не означает независимой проверки календаря организации.

Основные файлы: `apps/api/src/appointments/native-terms-evidence.ts`, `native-appointment-authorization.ts`, `apps/api/src/voice/native-appointment-call.ts`, `packages/contracts/src/native-appointment.ts`.

## 4. W3 — правильное завершение условной задачи

Добавлено проверяемое основание `end_call.noActionRequired`: буквальное условие из исходного подтверждённого задания и буквальный ответ собеседника, определивший ветвь без действия. Оно допустимо при отсутствии предпринятого/незавершённого действия. Неизвестное условие, неопределённое обязательство или неудачная обязательная запись не превращаются в успех.

Для выполненного appointment-действия по-прежнему требуется confirmed journal state. Основание завершения, состояние действия и итоговая оценка остаются разными сущностями: отключение само по себе не доказывает достижение цели. Полноту остальных задач и смысл условной ветви оценивает модель по исходному заданию; приложение проверяет происхождение цитат и состояние действия.

Live/backend-инструкции согласованы с этой семантикой. Прощание остаётся коротким: главный итог для представляемого лица, благодарность, завершение. Существующая recovery-логика использует тот же `end_call`, не повторяет обязательство и не требует повторного прощания. Проверки playback и свежего ответа сохранены.

## 5. W4 — оценка, отчёт и представление результата

Новые native-отчёты schema 9 получают полный исходный контекст независимо от наличия appointment authority. `native-summary-v3` поддерживает общий профиль и дополнение для назначений. Результат рассматривается по активной ветви задания; невостребованная ветвь не должна автоматически снижать оценку. Неизвестная применимость или невыполненная обязательная задача остаются неопределёнными/невыполненными.

Для appointment сохраняются проверки исходного разрешения, операции, слота, попытки, подтверждения собеседника и освобождения старой записи при переносе. Заявление собеседника о записи не выдаётся за независимое чтение его календаря. Общий профиль не может создать appointment outcome без соответствующего разрешения.

Разрешён максимум один адресный grounding repair с тем же входом, строгим валидатором и существующими бюджетами. Нормальный успешный отчёт не создаёт дополнительный запрос. Каждый физический repair-запрос учитывается отдельно, с причиной, путём поля, версией формата, request/operation ID и стадией `.grounding_repair`. Ограниченные диагностики сохраняются в существующем `response_metadata`; скрытые рассуждения и произвольный текст туда не записываются.

У длинного разговора проверяется и итоговый размер собранного входа. Если полное объединение невозможно либо завершающая оценка не получена, сохраняются извлечённые факты с исходными ссылками, итоговая оценка остаётся uncertain, а payload содержит `evaluationCoverage` с причиной и количеством частей. Это честная частичная обработка, а не гарантия полной оценки всех взаимосвязей между частями. Предупреждение одинаково доступно в карточке, копии, PDF и уведомлениях на семи языках.

Для новых отчётов используется summary-v8. Готовые исторические отчёты, закреплённые задания, canonical assessment и кредитные операции не переписываются. Повтор после неудачного native-v6/v7 может создавать новую v8 revision. Карточка и уведомления выбирают display revision; служебное уведомление дополнительно исправлено, чтобы не брать прежний canonical goal при новой отображаемой оценке. Сохранена совместимость legacy-отчётов без artifact ID в assessment.

Основные файлы: `apps/api/src/text-processing/{summary-source,native-summary,openai-text-processor,text-artifact-service,text-validation}.ts`, `apps/api/src/notifications/*report.ts`, `packages/contracts/src/summary-coverage.ts`, `apps/web/lib/derived-transcript-export.ts`.

## 6. W5 — телеметрия и экспорт

Архив v4 содержит `coverage.json`; корневой manifest показывает ограничения полноты. По каждой попытке различаются выбранная в периоде попытка и связанная история, native/legacy capture, состояние транскрипта, наличие trace manifest, разрывы последовательности, отсутствующие payload, dropped events, drain timeout, session closure, final usage, доступность аудио и удаление по отказу. Историческое отсутствие native trace не называется повреждением; удалённые данные не восстанавливаются.

Связи между preparation/compilation/snapshot/attempt, provider operations, backend requests, action revisions, text artifacts и usage сохраняются в исходных строках архива. Расходы, извлечённые из usage, не складываются повторно с исходным usage или суммой provider billing. Неокончательный Live usage явно не считается полным.

Производные измерения используют trace elapsed clock:

- начало trace → `session.started`; media admission → первая отправленная речь;
- остановка входной активности → следующая отправленная речь;
- backend response created → завершение, готовый tool call → отправленный output;
- closing mark → acknowledgement, drained playback → запрос отключения;
- последняя отправленная речь → запрос отключения и длительность запроса отключения;
- число closing/action recovery, ожиданий занятого backend, отменённых closing playback, grounding repair;
- размер начального контекста, максимальный наблюдавшийся backend input и доля потерь trace.

Каждая выборка ограничена 256 интервалами, отброшенные образцы подсчитаны. Отсутствующий интервал — unknown. Эти величины не приравнивают caption timestamps к слышимому аудио и не доказывают точный момент восприятия собеседником. Tool turnaround включает ожидание приложения до output; это не только время работы функции. Контекстные размеры — диагностические значения, а не точный запас токенов Live.

Сохранён отдельный ограниченный асинхронный канал trace: на аудиопути нет ожидания БД. Новые host events невелики; аудио сохраняется в trace как агрегированные метаданные. Долговечность расходов и действий не зависит от успешности необязательного trace. Privacy fences, очистка поздних событий и отзыв экспорта остаются обязательными.

Дополнительно исправлен account export: строгий контракт выгрузки теперь принимает `nativeAppointmentActions`. Ранее существующее поле могло приводить к HTTP 500 даже при пустом журнале.

## 7. W6 — расходы и тестовые запросы

Админка показывает разбивку по типу операции, стадии и модели: Live voice duration, reasoning backend, подготовка generation/audit/review, summary/repair, транскрипция и телефония. Разбивка считается по всей выбранной совокупности операций, до ограничения списка последних строк. Подкатегории не добавляются второй раз к общему итогу.

В деталях запроса доступны stage/outcome/model, pricing version, requested/actual tier, cost basis, источник usage и final/provisional/unknown. Успешное закрытие operation не заменяет final session usage. Ошибочный запрос с известными токенами остаётся расходом. Отсутствующий usage или неизвестный тариф не означает бесплатность. Служебный отчёт также учитывает длительность Live и её неполноту.

Для `apps/api/scripts/probe-native-profiles.mjs` обязателен отдельный диагностический OpenAI project и ключ, уникальный `NATIVE_PROBE_RUN`, явные `NATIVE_PROBE_MAX_USD` и `NATIVE_PROBE_MAX_REQUESTS`. До dispatch резервируется бюджет; новый запрос после исчерпания не отправляется. Повторное использование run ID запрещено. OpenAI-Project передаётся и речи, и Live. Журнал содержит только технические ID, резервы и доступный usage; ключи и разговор в него не попадают.

Резервы $1 для синтетической речи/Live и $5 для backend — консервативный локальный admission, **не гарантированный предел счета провайдера**. Окончательная стоимость сверяется по отдельному диагностическому проекту. Старым незарегистрированным тестам точная стоимость не приписывается. Диагностический проект не смешивается с расходами пользовательского приложения; разница с billing остаётся неатрибутированной, пока нет надёжных данных.

Во время этой реализации оплачиваемые model probes и реальные звонки не запускались.

## 9. Оставшаяся приёмка

Программные проверки не заменяют реальную акустику. Перед публичной beta нужны звонки с согласованным бюджетом и сравнением с удачной предыдущей версией:

1. Один вопрос и содержательный отрицательный ответ; удобство разговора, точное имя и краткое завершение.
2. Цена подходит → запись; цена выше → корректное завершение без записи; условие осталось неизвестным.
3. Бесплатная услуга, цена «от», доплаты, числовая коррекция до/после подтверждения; отсутствие лишнего повторного вопроса.
4. Подтверждение, перенос с освобождением старого слота, отмена, альтернативные окна; без повторного обязательства.
5. Перебивание, встречное прощание, отключение собеседником, автоответчик и повторный набор.
6. Отказ от разговора/записи с удалением; понятная причина неготового плана; полный и частичный отчёт.
7. Сверка одинаковой совокупности операций в админке и экспорте, финального usage и реального счета.

Не измерялись p95 слышимой задержки и качество модели на новой серии звонков. Не выполнены платные paired probes. Ограниченное объединение доказательств для разговоров сверх существующего итогового бюджета не расширялось: вместо ложной полноты показана частичная оценка.
