## Причина и исправление

В native режиме `conversation.started` возникает при начале речи ассистента, до результата асинхронного AMD. Старые правила считали этот факт достаточным, чтобы скрыть машинный ответ и запретить повтор. Дополнительно backend и PostgreSQL повторно запрещали создание копии при любой записи, хотя новая схема начинает запись сразу.

Добавлен общий предикат `nativeAutomatedAnswerHandled`: декларативная запись, конкретный machine/fax результат асинхронного AMD, уже отправленное действие завершения/сообщения, отсутствие явного согласия/отказа и подтверждённого содержательного ответа. Одного приветствия, отсутствия ответа, `unknown` или незавершённого AMD недостаточно.

- Lifecycle показывает `automated_answer` вместо `no_substantive_answer`; ожидающая/неопределённая оценка текста не скрывает известный машинный ответ.
- Интерфейс показывает результат AMD и состояние сообщения. Раннее приветствие не отображается как отдельное доказательство разговора с человеком.
- При завершённой подходящей попытке кнопка позволяет создать новую карточку с прежним планом для повторного подтверждения. Номер автоматически не набирается.
- Наличие декларативной записи в этом узком случае не запрещает повтор. Исходная запись остаётся в старой карточке и не копируется в новую.
- Использованный/зарезервированный кредит, явное согласие/отказ, подтверждённый ответ и существующее действие назначения сохраняют запрет. PostgreSQL дополнительно проверяет оба журнала действий под блокировкой исходной карточки.

Прочие правила повторов, новый review receipt, проверка владельца, идемпотентность параллельных запросов и запрет старта без нового подтверждения сохранены. Промты, ход живой беседы и пороги завершения не менялись. Проекция пересчитывается из существующих событий: ручной коррекции пользовательских данных не потребовалось.
