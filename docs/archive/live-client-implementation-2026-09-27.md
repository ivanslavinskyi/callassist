# Live client runtime: реализация и проверка

> Historical checkpoint, not the current runtime specification. As of 28 September,
> consent uses native `report_consent`, and `end_call` carries a reason without a
> scripted recap. See the [current runtime](live-unified-runtime.md) and
> [real-call review](live-call-review-2026-09-28.md). Results and pending items below
> describe the implementation at this report's date.


Дата: 27 сентября 2026. Ветка: `codex/live-unified-runtime`.
Основание: [согласованный план](live-runtime-orchestration-plan-2026-09-27.md).
Production этой работой не изменён; ручная телефонная приёмка новой версии обязательна.

## Что изменилось

- `OpenAILiveConversation` использует официальный `delegation.type=client`.
  `LiveTaskController` — единственный владелец запуска текстового backend.
  Native transcript → собранная реплика → standalone Responses → проверенное
  решение приложения. Отсутствие `session.delegation.created` больше не блокирует диалог.
- Голос, входная и выходная live-транскрипция остаются GPT-Live-1; PCMU 8 kHz
  проходит без перекодирования. GPT-6 Luna работает беззвучно через Responses,
  с `parallel_tool_calls=false`, `store=false` и строгим форматом результата.
- Одновременно выполняется одна задача, включая применение решения. Новая речь
  или текст инвалидируют старое решение. В контроллере нет словарей блюд, имён,
  конкретных ответов или фраз последнего звонка.
- Решения различают следующий вопрос, ожидание, фоновую речь, завершение,
  продолжение прерванного завершения и разрешённые действия с записью на время.
  Язык, тон и формальное обращение передаются обеим моделям.
- Итог — короткий пересказ, максимум 35 слов / 260 символов. Затем возможность
  поправить, прощание и hangup после действительного Twilio `mark`.
  `clear` и прерывание отменяют старый mark. Благодарность не запускает интервью заново.
- Семантическое согласие, AMD, immutable execution snapshot, языковая подготовка,
  post-call transcription/assessment и UI предыдущих изменений сохранены.

## Действия и сохранение

Миграция **0085_voice_action_intents.sql** добавляет журнал без изменения прежних
записей. На одну попытку допускается один spoken appointment request. До передачи
запроса собеседнику сохраняются snapshot hash, точные условия и зашифрованные
свидетельства. Версионированные состояния: sending, delivered, uncertain, confirmed.
При неопределённой доставке повторная запись автоматически не запрашивается.

Для назначения времени обычная автономная речь Live подавляется. Текст решения
проверяется относительно состояния действия; исходное PCMU буферизуется до проверки
native output transcript и лишь затем отправляется с playback mark. Это намеренная
задержка на потенциально обязывающих репликах. Дисклеймер, обычная информационная
беседа и прощание не получают такую полную буферизацию.

Подтверждение требует точного ожидающего предложения и более поздней реплики
собеседника, истолкованной в контексте. Более ранние ссылки могут сопровождать
подтверждение, но не заменяют его. Сохранённое подтверждение и проигрывание ответной
благодарности различаются: прерывание благодарности не стирает прежнее свидетельство.
Новая поправка рассматривается следующим решением. `confirmed` означает сообщение
собеседника, а не проверку внешнего календаря.

Журнал включён в ротацию ключей, проверку восстановления и выгрузку данных владельца.
Удаление данных звонка стирает его зашифрованное содержимое; остаётся техническая
запись, предотвращающая повтор действия. Admin archive содержит только корреляцию,
версию и состояние; содержимое реплик не добавляется в обычные telemetry-события.
Событие `conversation.task` показывает runtime version, фазу, ревизию и request ID.
Live seconds и все Responses requests, включая отброшенные, учитываются в ledger.
Отсутствие финального usage не подменяется нулевой стоимостью.

## Ограничения и восстановление

- Backend: HTTP deadline 15 секунд, одна повторная попытка при ошибке. Контроллер
  ограничивает выполнение и применение решения отдельно. Постоянная ошибка
  завершается понятной локализованной фразой, если голосовое соединение ещё доступно.
- Ожидание: проверка прогресса через 30 секунд, не более двух последовательных
  проверок без нового ответа. Это ограничение беты; очень длительное удержание
  линии не поддерживается бесконечно.
- Контекст: 96 000 символов / 4096 фрагментов; максимум 128 task requests.
  Ограничение приводит к честному завершению, не к выдумыванию результата.
  Общий предел звонка по-прежнему задаётся существующим admission policy и
  передаётся Twilio как `timeLimit` (по умолчанию 900 секунд).
- После разрыва соединения нет повторного выполнения внешнего действия или
  автоматического перехода работающего Live-разговора к другой модели.
- Новая заявка, перенос или отмена сверх утверждённого разрешения не разрешаются.
  Неопределённый запрос можно обсуждать, но его нельзя безусловно отправлять заново.
- Проверки семантики остаются модельными. Код обеспечивает порядок, авторизацию,
  provenance, playback и ограничение повторов; он не доказывает безошибочность
  распознавания речи или интерпретации любого ответа.
- Native аудиопротокол не предоставляет `response.done`. Полнота контролируемой
  реплики определяется native текстом, проверкой смысла, затиханием выхода и mark.
  Для немедленно проигрываемого дисклеймера это проверка перехода состояния,
  а не обещание, что ошибочная фраза никогда не будет услышана.

## Проверки

Проверяются selection/fallback, PCMU, consent и семь локалей, native transcripts,
одиночный запуск backend, новые реплики во время запроса/записи, исправления,
шум/ожидание, прерванное closing, устаревшие marks, ошибки/disconnect, ledger,
конкурентное создание action journal, CAS, encryption, deletion и key rotation.

Реальный аудиопробник `probe-live-client.mts` прошёл через production bridge:
синтетический PCMU → настоящий Live → native transcripts → настоящий Luna → вопрос,
короткое резюме, goodbye и hangup. Подменялись только Twilio playback/recording/hangup.
В последнем аудиопрогоне: 2 backend requests, 4 подтверждённых marks, ответы backend
около 1.87 и 1.85 секунды. Это не полная задержка телефонного ответа.

`probe-live-task-scenarios.mts`: **12/12** реальных Responses-сценариев, включая
исправление, thanks/noise при прощании, ожидание, отказ, неизвестный ответ,
последующее подтверждение времени, фоновое «да» и новые финансовые условия.
Проверка выявила и устранила конфликт приоритета ожидания с прежним ответом.
Опечатка проверки отрицания «сегодня, не вчера» исправлена в тесте, не в runtime.

Команды paid probes и порядок deployment: [runbook](live-unified-runtime.md).

Окончательный полный suite на неизменяемом во время прогона коде: **1 801 тест,
204 файла**, exit code 0 (API 1365 / 127; web 300 / 58; contracts 136 / 19).
Полные lint, typecheck и build: exit code 0 каждый. После review отдельно прошли
149 voice-тестов. Migration catalog: 85 файлов, latest 0085; `git diff --check` чистый.
Русский controlled-speech provider probe: **3/3** реплики в одной client Live session,
с native текстом и подтверждением проигрывания (22 секунды provider usage).

Self-review охватил single-flight/stale results, отмену playback, поздние native
фрагменты после закрытия проверяемой реплики, подтверждение во время нового ввода,
идемпотентность, privacy deletion/export/rotation, учёт отменённых запросов и rollback.

Локально применена 0085 только к `localhost:55432/callassist`. API перезапущен
27 сентября в 20:29 Europe/Zurich с `live`, `fallback=false`; frontend и readiness
вернули HTTP 200. UI: `http://localhost:3000/ru`. Существующий Twilio tunnel сохранён;
неподписанный запрос к публичному voice webhook получил ожидаемый HTTP 403.
Телефонный звонок человеку в этой проверке не выполнялся. Production не изменён.

## Ручная приёмка

Простой вопрос; длинная консультация; запись на время и неподходящие условия;
пауза/возврат; фоновая речь; исправление ответа; благодарность во время прощания;
отказ от согласия; voicemail. Проверить фактическую речь и задержку на телефоне,
live UI, автоматическую оценку и скачивание admin archive. Эту часть нельзя заменить
зелёным unit suite или симуляцией Twilio.

Production configuration после отдельного одобрения: `VOICE_RUNTIME_DRIVER=live`,
`VOICE_RUNTIME_LIVE_FALLBACK=false`. Repository default по-прежнему realtime.
Явно включённый legacy hybrid fallback сохраняется для совместимости; appointment
calls в нём остаются на подготовленном Realtime, имеющем прежние action guards.
Единый Live с fallback=false использует новые playback/action gates.

Миграция аддитивна и сохраняет прежние записи и запись старых типов событий.
При возврате к Realtime предпочтительно переключить driver в этом же релизе:
старый бинарник с закрытым перечнем telemetry events не умеет читать новый
`conversation.task`. Возврат к прежнему бинарнику после новых звонков требует
совместимого reader-патча; удалять события ради rollback нельзя. API и worker
обновляются согласованно. Миграцию 0085 обратно не удалять.
