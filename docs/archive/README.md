# Historical material

These files preserve earlier plans, audits, incidents, acceptance evidence and
implementation checkpoints. Their dates matter: they may describe retired code,
previous provider models, old schemas, historic test counts and obsolete limits.
They do not specify current behavior or prove the deployed environment.

Use the current [engineer guide](../engineer-guide.md),
[documentation index](../README.md) and [implementation record](../pre-production-implementation-2026-10-01.md).
Operational runbooks and VPS topology are intentionally kept outside version control.
