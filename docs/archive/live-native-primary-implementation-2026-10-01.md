# Live как основной транскрипт, ASR по запросу — 1 октября 2026

Реализация [согласованного плана](live-native-primary-on-demand-asr-plan-2026-10-01.md) на текущей ветке `codex/live-unified-runtime`. Проверка составных критериев summary «дата, время и обязательное место» **не входит в изменение**, согласно последнему указанию пользователя. Календарная логика и модельная оркестрация разговора не меняются.

## Хранение и интерфейс

- Основная вкладка — «Транскрипт Live». Она сохраняет допустимые native deltas, подтверждённые application playback (включая дисклеймер и прощание) и отдельное событие согласия с методом подтверждения. Событие согласия не выдаётся за дословную реплику человека. До-согласительная речь не восстанавливается.
- Источник и полнота независимы. При `incomplete` сохраняется доступный Live с предупреждением и известными интервалами потерь; причина старой неполноты не выдумывается. ASR автоматически не запускается.
- «По аудиозаписи» содержит явную кнопку. Открытие страницы/вкладки, callback, повторное соединение SSE и перезапуск worker не создают запросов ASR. Готовый исторический или запрошенный текст показывается из хранилища.
- В `final_transcripts` теперь отдельные родители `live` и `recording_asr` на attempt. Это расширение существующей таблицы, а не параллельная таблица артефактов: старые revision IDs, hashes и ссылки сохраняются. Поля snapshot `finalTranscript*` проецируют основной источник, `recordingTranscript*` — дополнительный. Для исторического звонка без Live остаётся явно обозначенный ASR.
- Каждая версия имеет собственные immutable revisions. Copy/PDF/перевод и ссылки на цитаты используют выбранный источник. Новый ASR не заменяет Live, не запускает второе summary и не пересчитывает стоимость звонка. Исторический результат, основанный на ASR, открывается в соответствующей вкладке.

## Надёжность

Новая `live_transcript_finalization` завершает текст независимо от готовности/наличия аудиозаписи. Очередь записи объединяет native fragments, playback receipts и capture finalization. Незавершённый capture терминального звонка восстанавливается после 20 секунд на завершение записи; доступные данные получают `partial`. Только изменение качества не создаёт новую текстовую revision.

Для новых fragments сохраняются ingestion sequence, время получения и attempt ID. Слова соединяются в порядке получения, временные координаты используются для размещения реплик. Повтор event ID или playback mark не дублирует текст; намеренные повторения слов сохраняются. Историческая последовательность восстанавливается детерминированно по имеющимся timestamp/ID, без обещания восстановить отсутствовавший receive order. Уже опубликованный исторический Live сохраняет свой текст/revision и summary: backfill добавляет ему диагностику, не переписывает исходные evidence.

`POST /api/call-briefs/:id/recording-transcript` проверяет владельца и атомарно сохраняет durable request с задачей. Старый `/final-transcript/retry` остаётся совместимым алиасом с теми же проверками. Повторные нажатия объединяются. ASR provider reservation требует request ID, действующую аренду job, активного владельца, доступное аудио и неистёкший срок; ID запроса записывается в provider ledger. Действующие ограничения запросов и retry сохраняются. Поздний ASR проходит текущий бюджетный admission отдельно для каждой операции: уже освобождённый резерв звонка не возобновляется. Успешные chunks повторно используются при совпадении записи, этапа, модели, ключа и fingerprint, включая следующую генерацию job.

Срок хранения 0/7/30 дней назначается однократно при готовности записи. Ранее назначенные сроки не меняются. ASR/retry не продлевают хранение. Для 0 дней удаление становится допустимым сразу после готовности записи, без ожидания транскрипции. Ручное удаление сначала сокращает deadline до текущего момента; новые запросы и поздняя публикация блокируются, а удаление у провайдера допускает durable retry. Удаление аудио сохраняет готовый текст; удаление данных звонка очищает оба источника, revisions и caches.

## Миграция и запуск

1. Остановить старые API/worker после проверки отсутствия активного звонка. Применить 0093 и 0094 до запуска v7.
2. 0093 разделяет источники, сохраняет существующие ссылки, отменяет старые автоматические ASR jobs и назначает отсутствующие recording deadlines. 0094 обновляет текущие технические описания в CMS, сохраняя историю публикаций/согласий. Неизвестные ручные изменения целевых текстов прерывают миграцию до публикации.
3. `corepack pnpm --filter @callassist/api db:backfill:live-transcripts` — dry run. Добавить `--execute` для публикации сохранённых native fragments. Backfill не вызывает модели, не создаёт новое summary/assessment; повторный запуск пропускает обработанные artifacts. Счётчики не содержат речь или персональные данные.
4. Запустить API с `VOICE_RUNTIME_DRIVER=live`, `VOICE_RUNTIME_LIVE_FALLBACK=false`, `OPENAI_LIVE_MODEL=gpt-live-1`. Версия telemetry — `live-managed-v7`; новый переключатель не требуется.
5. Проверить `/health/ready`, web, подпись и доступность webhook tunnel. Перед тестовым звонком ledger не должен содержать новых ASR operations без request ID.

## Проверка на телефоне

Начать с короткого немецкого звонка и хранением аудио 7 дней. Проверить дисклеймер, событие согласия, вопрос/ответ и прощание в основном Live; до явного запроса должно быть **0 новых recording-ASR requests**. Открыть вторую вкладку и убедиться, что это не запускает распознавание. Нажать кнопку один раз, дождаться дополнительного текста, проверить сохранность Live и исходного результата. Повторное открытие и запрос готового текста не должны создавать новые provider operations.

Затем проверить прерывание прощания и ранний hangup собеседника: partial допустим при реальной потере, смена источника и автоматический ASR — нет. Реальный звонок не заменяется unit-тестами; акустическая точность и поведение провайдера требуют этой приёмки.

## Проверки реализации

API: 1620 тестов / 139 файлов; фронтенд: 338 тестов / 63 файла; contracts: 236 тестов / 23 файла — все прошли. Полный серверный прогон выполнен на отдельной свежей локальной тестовой БД. Проверены typecheck пакетов, web lint, API и production web build, каталог миграций и public-copy consistency.

Локально применены 0093–0094, API/web перезапущены с `live-managed-v7`, Live fallback отключён. Dry run обнаружил 24 исторических capture; без вызовов моделей опубликованы 24 проекции, 5 partial, 7 unavailable, ошибок 0. Повторный dry run — 0 кандидатов.

Для двух последних звонков проверены основной `live_composed`, дисклеймер и событие согласия; прежние ASR revision IDs, готовые summaries и deadlines аудио сохранены. После переключения: **0 новых OpenAI operations, 0 явных ASR requests, 0 автоматических ASR jobs**. Исходники совпадают с локальным manifest. Новый реальный телефонный звонок ещё не выполнялся.

Web и `/health/live`, `/health/ready` — HTTP 200; приватный API через публичный tunnel — 404; webhook без подписи — 403; корректно подписанный webhook с несуществующим call ID — безопасный 404. Активных звонков нет, исходящие звонки и бюджетный gate включены, необходимые credentials присутствуют. Секреты в отчёт не включены.
