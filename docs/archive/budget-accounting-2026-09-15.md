# Исправление денежного контроля, 15.09.2026

Этот документ заменяет денежную семантику из [отчёта 14.09](beta-controls-2026-09-14.md).
Актуальный backlog — [roadmap](mvp-plan.md), B05/B09/B12.

## Причина завышения

14 USD были резервом `7 × 2 USD/мин`, а не стоимостью звонка. Каждый text-запрос,
включая бесплатную модерацию OpenAI, дополнительно резервировал 0.50 USD. Все
резервы оставались занятыми 24 часа: существующий ledger токенов и стоимости
Twilio не участвовал в допуске следующего запроса.

## Новый расчёт

Занятый бюджет = стоимость, сообщённая провайдером + стоимость по сохранённому
usage и версионным тарифам + резервы ещё не подтверждённых расходов.

- OpenAI moderation: 0 USD. Новые проверки не создают денежного резерва;
  исторические связанные резервы также учитываются как нулевые.
- Подготовка, перевод и ASR: при достаточном usage резерв заменяется расчётом
  по токенам/длительности. Cache read/write учтены отдельно, reasoning повторно
  не начисляется. Ошибка формата ответа не отменяет оплаченные токены.
- Звонок: при допуске резервируется полная максимальная длительность. После
  терминального статуса Twilio, успешного завершения учтённых Realtime-сессий и
  получения расходов/usage используется стоимость connectivity в USD и
  рассчитанная стоимость Realtime/ASR. Отдельно зарезервированные text/ASR
  операции не считаются второй раз внутри звонка.
- Для Media Streams, recording и одного месяца хранения остаётся allowance
  0.01 USD на фактически тарифицируемую минуту. Это округлённая оценка, а не
  подтверждённая строка счёта. Доход/пользовательские кредиты сюда не входят.
- Неизвестная модель, неполные метрики, потерянный ответ, неуверенное закрытие
  соединения или отсутствие USD price сохраняют резерв. SMS/email пока также
  используют свои allowances; отдельного reconciliation их invoice нет.
- Превышение фактического расхода над резервом учитывается полностью. Поздние
  записи ledger попадают в следующий расчёт; история не удаляется и не
  переписывается. Окно привязано к времени исходного резервирования — 24 часа.

Расчёт выполняется под общей PostgreSQL-блокировкой допуска при чтении панели
и перед новым резервом. Запись provider usage не захватывает эту блокировку:
порядок блокировок API/worker не меняется. Миграция **0072** добавляет индекс
по попытке звонка, чтобы сверка не сканировала всю историю операций.

В админке `/admin/system#beta-controls` отдельно показаны provider-reported cost,
usage calculation, pending reserves, занятая/доступная сумма и резерв следующего
звонка. Поле API `reservedMicros` сохранено для совместимости; теперь это общий
занятый бюджет, его составляющие возвращаются отдельными полями.

## Локальная калибровка

Настройки revision **3**, изменение с причиной в `beta_control_audit`:

| Параметр | Значение |
| --- | --- |
| Бюджет / скользящие 24 часа | **20 USD**, без изменения |
| Максимальная длительность | **420 секунд**, без изменения |
| Резерв минуты звонка | **0.60 USD** |
| Резерв семиминутного звонка | **4.20 USD** |
| Резерв платного text-запроса | **0.15 USD** |

По сохранённым данным трёх прежних CH-звонков: 174/225/94 секунды,
connectivity 0.5406/0.7208/0.3604 USD, рассчитанный OpenAI usage
0.431571/0.671147/0.154199 USD. OpenAI-суммы включают записанные подготовку и
обработку результата; это расчёт по известным метрикам, не полная сверка invoice.
Резерв оставляет запас относительно этой небольшой выборки. Он редактируется
в админке; при изменении географии, моделей или тарифов нужна новая калибровка.
Bootstrap defaults для новой базы остаются защитными до настройки оператора.

После исправления локальный занятый бюджет: **9.653991 USD**, из них
**0.153991 USD** рассчитанного usage и **9.50 USD** pending. Остаток:
**10.346009 USD**, допуск звонка проходит. В pending сохранены два запроса с
тайм-аутом (1 USD) и 17 прежних диагностических запросов без связанного
persisted usage (8.50 USD). Их нельзя представлять как фактические расходы;
необоснованного обнуления или восстановления недостающих метрик не было.

## Проверка и оставшаяся приёмка

35 целевых проверок pricing/accounting/beta integration, 7 проверок admin
operations и 5 проверок каталога миграций; API/web typecheck, web lint. Интеграции используют отдельные базы:
конкурентный допуск после reconciliation, неизменность исходных резервов,
запоздавшая стоимость, превышение резерва, повторное чтение и окно 24 часа.
Платные запросы/звонки для этих тестов не отправляются.

Миграция 0072 применена локально, API перезапущен после проверки отсутствия
активных звонков/подготовок. Readiness API и главная сайта отвечают 200;
тоннель и реальные драйверы сохранены. Повторный допуск звонка по бюджету проходит.

Перед публичным GO остаются B09: реальные длительные звонки, отказы и стоимость
после текущего релиза; B12: upstream billing alerts и доставка тревог оператору.
Лимит приложения использует оценки и не гарантирует точного ограничения invoice.
Аренда номера и долговременные расходы аккаунта требуют отдельного контроля.

Тарифные источники, проверены 15.09.2026:

[GPT-4o Transcribe](https://developers.openai.com/api/docs/models/gpt-4o-transcribe),
[бесплатная moderation](https://help.openai.com/en/articles/4936833),
