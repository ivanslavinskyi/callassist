# Исправление дисклеймера и восстановления Live — 29 сентября 2026

Основание: [разбор последнего звонка](live-call-failure-review-2026-09-29.md). Первая неподходящая реплика проваливала существующую проверку содержания и немедленно закрывала звонок. Точный текст того звонка не сохранён; его нельзя восстановить из журналов.

## Изменение

- Инструмент согласия включается после подтверждения проигрывания дисклеймера через Twilio mark. При уточняющем вопросе он временно выключается. Старые backend-продолжения сохраняют исходную версию разрешений.
- Если первая попытка обязательного дисклеймера не прошла проверку содержания либо не завершилась вовремя, приложение один раз запрашивает полный текст заново. Используются существующие отмена, очистка аудио и номер поколения. Решение не распознаёт отдельные фразы и не зависит от языка или задачи.
- Повтор не распространяется на обязательства, прощание и неподтверждённое проигрывание. После второй неудачи сохраняется ограниченное техническое завершение; бесконечных повторов нет.
- Событие `disclosure.started` теперь возникает после проверки содержания, перед отправкой mark. Подтверждение самого mark по-прежнему требуется для перехода к согласию. Одна служебная реплика не создаёт такое событие.
- При окончательном речевом сбое `conversation.ended` сохраняет `failureCode` и `failurePhase`; захват расшифровки отмечается неполным. Текст собеседника до согласия не сохраняется.

## Гонка при согласии

Синтетические прогоны выявили, что Live может делегировать ответ до последнего фрагмента распознанной речи. Проверка свежести правильно отклоняет такой результат, но инструкция «делегируй заново» не гарантировала продолжения: модель иногда оставалась ждать.

После завершения устаревшего backend-продолжения приложение один раз вызывает штатный `response.create`, который создаёт новую делегацию с текущим контекстом. Повтор ограничен текущим вопросом о согласии и не запускается, если другая backend-операция уже выполняется. Проверки актуальности ответа и запрет записи без принятого согласия сохранены. Новых таймеров, классификаторов, моделей и миграций нет.

Поведение команды сверено с [Live API reference](https://developers.openai.com/api/reference/typescript/resources/live) и проверено реальными событиями API: новый `session.delegation.created` получил новый идентификатор и более поздний `offset_ms`.

## Проверки

- API: 175 тестов в 9 наборах, включая controlled speech, подготовку, согласие, исправление ответа, завершение, назначение встреч и телеметрию; TypeScript без ошибок.
- Contracts: 143 теста в 20 наборах; TypeScript без ошибок.
- Повтор дисклеймера проверен на русском, немецком, французском, итальянском и английском синтетическими событиями. Проверены второй отказ, таймаут проигрывания, устаревшие mark и backend-продолжения, отказ в согласии и отсутствие параллельного повторного запроса.
- Три финальных прогона с настоящим Live/Responses API и синтетическим собеседником завершились успешно:

| Прогон | Результат | Длительность |
| --- | --- | --- |
| Немецкий | Дисклеймер → согласие → запись → задача → прощание | 52,4 с |
| Русский | Дисклеймер → согласие → запись → задача → прощание | 51,5 с |
| Русский с принудительно неверной первой репликой | `different` → повтор полного дисклеймера → согласие → запись → задача → прощание | 67,5 с |

В третьем прогоне только первая инструкция в тестовом сокете заменена на «Одну секунду, я обрабатываю». Восстановление выполнял рабочий код. Первое неверное высказывание не попало в сохранённую расшифровку как подтверждённый дисклеймер.

Журналы: `.tools/disclosure-fix-final-de.log`, `.tools/disclosure-fix-final-ru.log`, `.tools/disclosure-fix-final-recovery.log`. Вспомогательный стенд: `.tools/disclosure-fix-probe.mts`.

В этих прогонах Twilio, запись и отключение симулированы, хранилище работает в памяти. Это проверка реального поведения моделей и приложения, но не новый телефонный звонок. Формулировки обычных реплик остаются генеративными; исправление не гарантирует дословную речь модели или отсутствие любых служебных оборотов. Поток аудио не буферизуется дополнительно, поэтому первая неверная реплика ещё может быть слышна до восстановления.

Ранние экспериментальные прогоны с одним лишь указанием модели повторить делегацию проваливались; они не считаются успешной проверкой финального решения.
