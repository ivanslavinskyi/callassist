# Live v6: единый транскрипт, языковой контекст и адресат финала

Дата: 1 октября 2026. Ветка: `codex/live-unified-runtime`.
Продолжение [реализации v5](live-stabilization-implementation-2026-10-01.md).
Изменения согласованы пользователем после разбора немецкого звонка о выборе обеда.
Новый звонок на телефоне остаётся отдельной приёмкой; синтетические проверки её не заменяют.

## Что произошло в звонке v5

Попытка `9fbf56af-296b-4dad-adc0-04fe588e0af9`, звонок
`ced14b37-4673-4171-9411-7836cdce57f3`, 1 октября, 09:45:27–09:46:32 UTC.
Согласие принято, запись началась, ответ про пиццу получен. Шесть backend-делегаций
завершились успешно. Прощание воспроизведено до подтверждённого Twilio mark;
`playback_complete` в 09:46:32.300Z, `agent_hangup` в 09:46:32.330Z.
Этот звонок завершил ассистент. Ошибки завершения из предыдущего звонка здесь не повторились.

Остались три проблемы:

1. При отправке любого application-rendered task audio v5 выставлял
   `clippedTaskSpeech=true`. Даже целиком доставленное прощание делало capture
   `incomplete`, запускало полную запись через ASR и показывало старое разделение
   «во время звонка / итоговая расшифровка». В данном звонке было семь ASR-запросов.
   Резервный ASR и переключатель существовали раньше; v5 ошибочно сделал этот путь штатным.
2. Нативные входные deltas содержали кириллическое фонетическое распознавание немецких
   ответов, тогда как recording ASR распознал `Ja, natürlich` и `Ich möchte Pizza`.
   Русский UI/plan-review в execution context не передавался. Однако имя `Иван`
   сохранялось дословно в parties, objective, opening и критериях. Кроме того,
   полный frontend prompt содержал общую подсказку `Russian Шпрохли` для имени
   ассистента даже при немецком языке. Первоначальный анализ учитывал только имя
   собеседника и был неполным. Обнаружение обеих вставок не доказывает, что именно
   они вызвали ошибку входного распознавания: это остаётся вероятным влиянием контекста.
3. Backend вернул `Иван möchte Pizza zum Mittagessen.`. `resultSummary` был описан
   как фактический итог, но без явного адресата. Дополнительная инструкция ошибочно
   относила все предпочтения к представляемому заказчику. Приложение дословно
   озвучило полученный текст — это не ошибка renderer.

## Реализованный контракт

Штатный итоговый транскрипт сохраняет слова и временные метки native Live. Для
конечных реплик приложения добавляется точный исходный текст renderer после
актуального подтверждения воспроизведения. Receipt содержит session ID, уникальный
Twilio mark, время отправки, время получения подтверждения и длительность аудио.
Эти интервалы приблизительные: receipt не является точной меткой каждого слова.

Receipt сохраняется в той же последовательной очереди, что native deltas и
финализация capture. Медленная запись прощания в БД не позволяет опубликовать
завершённый транскрипт раньше самой реплики. Старые/отменённые marks не создают
доставленных реплик. Отправленный, но не подтверждённый или прерванный фрагмент
оставляет capture неполным. Ошибка render до выпуска аудио сама по себе не
означает, что из транскрипта пропали услышанные слова.

Запоздалый native-текст до интервала подавления сохраняется без возобновления
речи или backend. Полностью подавленный текст отбрасывается; пересечение границы
не обрезается предположительно по словам и требует fallback. Действительно
оборванное native audio, потеря capture, ошибки сохранения или ненормальное
завершение Live также сохраняют резервную расшифровку записи.

Источники результата:

| Источник | Содержание |
| --- | --- |
| `live_native` | Только нативные реплики Live |
| `live_composed` | Нативные реплики плюс подтверждённые реплики приложения |
| `recording_asr` | Резервная расшифровка записи при неполном capture |

Это один канонический транскрипт. У сегментов сохраняется происхождение; summary,
assessment, переводы, copy и PDF используют одну неизменяемую revision/hash.
Для `live_composed` UI не показывает вторую конкурирующую версию. Подпись источника
честно сообщает о добавлении подтверждённых реплик приложения. Исторические ASR
результаты не переписываются.

## Язык и обращения

Для recipient и represented person введены отдельные `original` / `spoken`
идентичности версии 1. Новые execution snapshots фиксируют обе формы. Исходная
компиляция, написание личности и разрешения на действия остаются неизменными.
Речевое представление латинских языков поддерживает детерминированную передачу
русских/украинских букв латиницей (`Иван` → `Ivan`); для русского звонка написание
сохраняется. Это подсказка произношения, не официальная транслитерация документа.

Проекция применяется только к известным именам в человеческом тексте. Она не
переводит произвольный русский текст, не меняет входной transcript и не заменяет
проверку языка. Существующий pre-call language audit проверяет ту же речевую
проекцию; новых модельных запросов или классификаторов на ходе звонка нет.
Общая инструкция имени ассистента использует IPA и подсказку выбранного языка,
без вставки русского написания в немецкий prompt.

Frontend и backend различают заказчика и непосредственного собеседника.
`resultSummary` явно является текстом, который будет произнесён собеседнику:
его собственный ответ пересказывается во втором лице с утверждёнными Sie/du
или соответствующей формой другого языка. Третье лицо сохраняется для другого
человека, например клиента, чью запись подтверждает администратор. Результат не
обещает пересылку, доставку, callback или иной неисполненный шаг.

Нет жёсткого обещания, что native распознавание никогда больше не выдаст чужую
письменность: исправлены источники смешения в нашем контексте, но сами provider
deltas сохраняются дословно. Независимого распознавателя или скрытого перевода
нативных реплик не добавлено.

## Где остался Realtime

Единый resolver `config/voice-runtime.ts` используется runtime factory, проверкой
конфигурации и выбором async AMD. При отсутствующих флагах он выбирает
`unified_live`, fallback выключен. Ошибка Live не меняет этот режим.

| Конфигурация | Режим |
| --- | --- |
| По умолчанию / `VOICE_RUNTIME_DRIVER=live`, fallback=false | Один Live, включая согласие и task |
| `VOICE_RUNTIME_DRIVER=realtime` | Явно выбранный старый Realtime |
| Live и `VOICE_RUNTIME_LIVE_FALLBACK=true` | Явно выбранный старый гибридный pilot |

`OpenAIRealtimeBridge` остаётся в двух явных ветках создания выше и в их тестах.
Названия `realtime.ready`, `REALTIME_AGENT_HANGUP_ENABLED`, методов учёта операций
и общие утилиты в каталоге `realtime/` сами по себе не открывают старую сессию.
Startup log теперь печатает конкретный mode. Устранено отдельное устаревшее
решение AMD: раньше отсутствие driver давало Live runtime, но синхронный AMD.
Production этим изменением не развёртывался и заново не инспектировался.

## Проверка и локальный запуск

- Добавлена миграция `0092_application_playback_transcript.sql`: nullable receipt
  в transcript_segments и новый источник final_transcripts. Применяется до новых
  API/worker; downgrade ограничения source после новых результатов недопустим.
- Сквозной тест проходит consent → вопрос/ответ → end_call → mark → задержанная
  запись receipt → session.closed → единый final transcript без recording ASR.
- Проверены late deltas, пересечение границ, исходное написание имён, все точки
  включения Live-контекста, replay recording callback, retention и PostgreSQL.
- Provider-проверка `gpt-6-luna`: 6/6 синтетических сценариев. Получены
  `Sie möchten Pizza zum Mittagessen.`, `Du möchtest Pizza zum Mittagessen.`,
  `Nina möchte Pizza zum Mittagessen.` для другого человека; прямое обращение
  также сохранено на французском, английском и русском.
- Автоматические результаты и состояние локальных процессов фиксируются в
  `.tools/` и `.tools/runtime/stabilization-state.json`; ключи и записи звонков
  в Git не добавляются.

Проверено 2 184 уникальных теста: API 1 613, contracts 236, web 335. Полный API
прогон выявил два дефекта тестовых данных (повтор providerCallId и изменённые
имена без обновления frozen fixture); они исправлены, затем повторно прошли
все 313 voice-тестов и четыре memory/PostgreSQL сценария транскрипта. В эту
проверку входят два дополнительных теста запоздалых фрагментов. Typecheck всех
пакетов, production build и web lint проходят.

Локальный v6 запущен и проверен 1 октября в 12:34 Zurich: startup mode
`unified_live`, fallback=false, agent hangup=true, API liveness/readiness и web
HTTP 200. Миграции совпадают с каталогом через 0092; активных попыток и старых
summary jobs нет. Текущий туннель сохранён, закрытый маршрут возвращает 404,
webhook без подписи — 403. Исходники совпадают с проверенным manifest. Звонки
и бюджет разрешены; тестовый исходящий звонок агентом не запускался.
