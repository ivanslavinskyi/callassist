## Имплементация

1. После проверки многошагового звонка обработка речевых ответов возвращена native
   Live delegation: приложение сохраняет evidence, но не запускает второй response.
   Продолжение после результатов инструментов, ограничение времени ожидания,
   защита от устаревших решений и повторных действий остаются у приложения.
   Поддержка резюме через идентификаторы реплик, без дословного копирования текста.
   Короткий итог → возможность исправления → прощание → подтверждённое Twilio mark
   → hangup. Благодарность во время завершения не оставляет бесконечное ожидание.
   Согласие, appointments, approved snapshot и authorization остаются у приложения.
2. Общая модель отображения временных и сохранённых native фрагментов: стабильные
   карточки, без дубликатов и перестроения списка при сохранении; без HTTP snapshot
   на каждое слово. Сохраняем исходные timing/evidence, reconnect и ручную прокрутку.
3. Показываем действительно воспроизведённый дисклеймер и отдельно системный факт
   согласия с временем/способом во всех семи UI локалях. Не выдумываем дословное
   согласие; не сохраняем произвольную речь до согласия. Буфер ответа около границы
   воспроизведения ограничен; преждевременное «да» не даёт разрешения.
4. Подготовка Live параллельно дозвону/AMD: привязка к попытке, отсутствие речи и
   task context до admission, TTL, очистка при отказе/автоответчике/ошибке/остановке,
   provider ledger для всей сессии. Synchronous AMD сохраняется; его пороги без
   отдельного сравнения реальных сценариев не меняем. Исключаем дублирующие фразы
   во вступлении там, где это допускает уже утверждённый план. Не переписываем
   immutable approved snapshot и не обещаем устранить задержку AMD.

## Проверки и приёмка

- Сценарий ответа «Pizza» использует native delegation без второго запуска backend.
- Автоделегация, задержанный transcript, исправление и повторные callback не дают
  конкурирующих решений/двойного hangup; благодарность и просьба подождать различаются.
- Завершение только после соответствующего uncleared mark; прерывание отменяет его.
- Consent до/после границы, отказ, DTMF, ошибка записи; отсутствие pre-consent history.
- 28 фрагментов вступления, переход partial→persisted, reconnect и завершённый звонок.
- Prewarm: busy/no-answer/machine/unknown, timeout, неверная привязка, shutdown, usage.
- Полный test/lint/typecheck/build, self-review privacy/billing/races, затем ручные
  звонки через локальный Twilio tunnel. Live, fallback=false. Merge/deploy отдельно.

Документация протокола: https://developers.openai.com/api/docs/guides/live-delegation
и https://developers.openai.com/api/docs/guides/live-conversations.

## Уточнения реализации

- Фрагменты сохраняются раздельно как native evidence. Общая карточка собирается
  в UI до и после сохранения по одним event ID; убран HTTP-запрос на каждое слово.
- Дословный ответ согласия не сохраняем: показываем реальный системный факт и метод.
  Дисклеймер — фактический native output после подтверждённого воспроизведения.
- Подготовка запускается подписанным ringing/answered callback, TTL 45 секунд,
  максимум 64 ожидающих сессии на процесс. Ожидание учитывается провайдером;
  при нескольких API-процессах для выигрыша нужна affinity callback/stream.
- Старые утверждённые вступления не меняем. Для новых планов сокращены рекомендации
  по вводным фразам; обязательные поля и readiness question остаются совместимыми.
