# Упрощение языкового workflow после пользовательского теста

Дата: 9 сентября 2026. Объём: выбор языка при подготовке задания и чтении результата; отдельная регрессия автоматического завершения звонка.

## Основание и вывод

Предоставленный пользователем скриншот завершённого звонка показывает отдельные selector для сводки, расшифровки и исторического плана, а также вкладку готового перевода вместе с кнопкой его показа. Скриншот просмотрен; он содержит личные данные и не добавляется в репозиторий.

Это ограниченный разбор конкретного workflow, а не повторный полный аудит продукта. Он не доказывает количественное влияние на конверсию или время выполнения задачи.

| Наблюдение | Почему это мешает основному сценарию | Решение |
| --- | --- | --- |
| Независимые языки сводки, расшифровки и плана | Пользователь должен разбираться в трёх настройках для одной потребности — понять свой звонок. Для отдельного перевода третьему лицу польза возможна, но такой сценарий здесь не установлен. | Один сохранённый язык задачи; исходный текст остаётся доступен. |
| Готовая вкладка перевода и кнопка «Показать перевод» одновременно | Два control выполняют одно действие и визуально конкурируют с копированием/экспортом. | Одна кнопка генерации до готовности, затем оригинал/перевод. |
| Отключённый selector языка в истории | Создаёт ожидание доступной настройки, которую нельзя изменить. | Убрать настройку после утверждения; оставить чтение оригинала и перевода. |
| Предпочтение аккаунта выше определения ввода | При скрытом выборе формы результат может неожиданно оказаться на другом языке. | В новой auto-задаче определение имеет приоритет; аккаунт задаёт только резервный вариант. |

Архитектурное разделение `uiLocale`, `callLocale`, `taskContentLanguage` и `artifact.targetLanguage` сохраняет смысл: новые UI-словари не меняют звонки, сохранённые планы или исходные данные. Избыточным оказался объём настроек на экране, а не само разделение доменных значений.

## Уточнённое поведение

1. В новой форме выбирается язык звонка. Compiler определяет язык запроса без отдельного запроса на каждый символ.
2. До утверждения рядом с планом доступно одно раскрываемое исправление языка плана и результата. Оно нужно для короткого, смешанного или ошибочно распознанного ввода; ограничений на число исправлений до утверждения нет.
3. Новая auto-задача: поддержанное определение → резервный язык аккаунта → поддержанный UI fallback → английский. Ручной выбор имеет приоритет; существующий контекст сохраняется.
4. Сводка использует язык задачи. Расшифровка переводится по кнопке на этот же язык; готовый перевод переключается с оригиналом без дополнительных меню.
5. Ошибки, повтор, ожидание, ссылки на исходные реплики, copy/PDF и чтение готовых артефактов при отключённой генерации сохраняются. Прежние артефакты и receipts не переписываются.

## Проверка

Контракт: 18 языковых тестов и 2 API language-workflow теста прошли; contracts/API typecheck прошли. Включены приоритет определения, неопределённый/смешанный/неподдержанный ввод, резервный выбор и неизменность всех прежних источников выбора.

Web: 30 профильных тестов в 7 файлах, typecheck и lint прошли. Новые регрессионные проверки охватывают чтение/экспорт оригинала до готовности перевода, привязку к версии источника и фиксированный язык задачи.

Браузерная проверка пройдена в Codex in-app browser на отдельном экземпляре с in-memory хранилищем и mock-провайдерами, на `127.0.0.1:3100` / `127.0.0.1:4100`. Проверены:

- немецкая новая форма без дополнительного selector текста и с одним локализованным английским языком звонка;
- готовая сводка без меню языка, одна кнопка перевода на русский до генерации и переключатель оригинал/русский после неё;
- возврат к оригиналу по ссылке из сводки с фокусом на правильной исходной реплике;
- смена DE → EN интерфейса при сохранённом русском языке результата и немецком языке звонка;
- развёрнутый исторический план с двумя вариантами чтения и без отключённого selector;
- создание нового задания, раскрытие исправления языка, сохранение русского и автоматическое сворачивание настройки после успешного ответа;
- резервная настройка аккаунта: свёрнутое текущее значение, пояснение при раскрытии, доступный сброс к языку интерфейса и сохранение выбранного русского после перезагрузки страницы.

Результат с готовым переводом и компактное исправление языка плана были сняты и просмотрены. По решению пользователя исходные скриншоты удалены из репозитория и не версионируются; здесь сохранены текстовые результаты проверки. Сопоставление со скриншотом пользователя подтверждает устранение дублирующих control; данные и размеры скриншотов отличаются, поэтому это не сравнение вёрстки по пикселям. Полностраничный кадр с ошибкой склейки отклонён и удалён; использованы обычные кадры viewport.

Фикстура явно помечает тексты `[QA MOCK ru]`, а не выполняет настоящий перевод. Её deterministic compiler возвращает неопределённый язык: в новом задании был проверен fallback и ручное исправление; detection-first подтверждён отдельными контрактными тестами. Платных LLM-запросов, реальных аккаунтов и новых телефонных звонков в этой проверке нет. Новый production build, полная мобильная/доступностная проверка и качество перевода каждой языковой пары здесь не заявляются.

После проверки временная вкладка закрыта, три подтверждённых QA-процесса остановлены, автоматические изменения Next для QA-каталога отменены с сохранением прежних изменений пользователя. Рабочий API остаётся ready, web возвращает 200, процесс прежнего тоннеля работает.

Завершение звонка: причиной был отсутствующий флаг локального запуска. Он сохранён и применён перезапуском API; 55 профильных тестов прошли. [Подробности и границы проверки](hangup-runtime-restoration-2026-09-09.md).
