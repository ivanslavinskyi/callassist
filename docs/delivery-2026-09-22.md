## Schema и rollout

Текущий каталог исходников — **0001–0079**. Применённые миграции целевого окружения
проверяются отдельно; наличие файла в Git не означает его применения.

| Миграция | Назначение / что проверить |
| --- | --- |
| 0075 | Recipient opt-out: отдельный Verify Service, общий стабильный contact HMAC key, backfill контактов |
| 0076 | Usage supplements/effective usage и provider billing snapshots; проверить конфигурацию billing sync и границы account/project totals |
| 0077 | Notification settings/queue/audit; defaults disabled, включение адресатов и реальная доставка требуют отдельной приёмки |
| 0078 | OG assets/versions/publications/audit; миграция перед API, шрифты/лого в API build, fallback PNG в web |
| 0079 | Telemetry queue/parts/audit/privacy triggers; миграция перед API/worker, общий keyring, export consumer и heartbeat |

**0079 в этой работе применялась только к тестовым БД.** Для рабочего приложения
нужны штатная миграция и перезапуск новой сборки API/worker. Экспорт использует
PostgreSQL 17; `ADMIN_TELEMETRY_EXPORT_ENABLED=false` отключает функцию.
Очередь отдельная от последовательного обработчика ASR; данные архива хранятся
зашифрованными частями 24 часа. Удаление контента/запрос account deletion/смена
role или status глобально отзывает существующие выгрузки. Это сознательно более
консервативная реализация, чем точечный отзыв по ещё не определённому составу.

Ротация использует **20 ciphertext families**, recovery проверяет **29 critical
tables**. После восстановления backup перед открытием трафика обязательно отозвать
восстановленные архивы по [runbook экспорта](admin-call-telemetry-export.md), затем
выполнить обычный deletion/suppression replay. OG assets входят в обычный backup.
