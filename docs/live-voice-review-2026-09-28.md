## Что пока не доказано

При данном плане и текущей конфигурации код выбирает `audio.output.voice=cedar`.
Однако отправленный голос и подтвержденные сервером поля `audio.output.voice`
не сохранены в телеметрии этого звонка. Обработчик `session.started` использует
ID; `session.updated` не проверяет сохранение конфигурации голоса.

Поэтому нет основания утверждать, что приложение явно переключило `cedar` на
`marin`. Рабочие гипотезы — изменение тембра внутри генерации одной сессии либо
ошибка провайдера на переходе через consent delegation. Данных для выбора между
ними нет. Настройка voice ID и воспринимаемый тембр — разные измерения.

Запись начинается после согласия; исходного аудио дисклеймера в Twilio-записи нет.
Текст дисклеймера не позволяет восстановить тембр. Сессия запускается с `store:false`.
Диагностическую запись до согласия нельзя незаметно включать для реальных получателей;
сравнение обеих фаз следует воспроизвести на согласованном тестовом аудио.

## Форма выбора ассистента

`create-call-form.tsx` отправляет `assistantProfileId`. Серверная нормализация
берет `agentName` и `voiceGender` из `ASSISTANT_PROFILES`. Эти значения попадают в
утвержденный snapshot. Live выбирает голос по сохраненному `runtime.voiceGender`.
В последнем звонке эта цепочка не потеряла мужской выбор.

| Профили | Live по умолчанию |
| --- | --- |
| Sebastian, Daniel, Martin | cedar |
| Anna, Sofia, Maria | marin |

Это шесть имен и два базовых голоса, не шесть различных тембров. Имя попадает в
инструкции идентичности, но не выбирает отдельный голос провайдера. Дисклеймер
представляет ИИ-ассистента без выбранного имени. Сама схема работает с Live,
но недостаточна для продукта, обещающего выбор конкретного голоса.

Дополнительные пробелы:

- Конкретный voice ID не зафиксирован в approved runtime / попытке. Изменение
  `OPENAI_LIVE_MALE_VOICE` или `OPENAI_LIVE_FEMALE_VOICE` меняет звучание будущих
  запусков, сохраняя то же имя и пол в интерфейсе.
- Live использует собственные переменные окружения; настройка только
  `OPENAI_REALTIME_*_VOICE` на native Live не действует.
- Значения Live voice env не проверяются по каталогу допустимых голосов.
- Текущие проверки транспорта не устанавливают акустическую стабильность;
  отсутствует проверка принятого сервером голоса между фазами.

## Предлагаемое решение

1. Сначала добавить минимальную диагностику: requested/confirmed voice, model,
   session ID, runtime version и этап на `session.started` / `session.updated`.
   Сопоставлять подтверждения с запросами; не хранить вместе с этим аудио,
   ответы получателя, токены и полные инструкции.
2. Проверить обе фазы в одной сессии на согласованном тестовом материале, используя
   тот же немецкий язык, PCMU 8 kHz и переход через `report_consent`. Отдельно
   проверить DTMF-переход без consent delegation и женский профиль. Это различит
   проблему принятой конфигурации и акустический дрейф при неизменном voice ID.
3. Ввести явный каталог голосов приложения. На ближайшем этапе показывать два
   проверенных голоса; если нужны имена персонажей, обозначать их отдельно от
   голоса. Не выдавать несколько имен с одним voice ID за разные голоса.
4. Сохранять выбранный профиль, версию каталога и разрешенный provider voice ID
   до подготовки Live-сессии; использовать этот выбор на всех фазах. Ограничить
   конфигурацию допустимым каталогом, а не произвольными строками окружения.
5. Добавить проверки male/female, подготовки сессии, перехода после согласия,
   продолжения после backend tool и отсутствия второй сессии. Превью голоса должно
   соответствовать Live и поддерживаемому языку, а не другому TTS-движку.

Одна сессия остается правильной архитектурой. Принудительно повторять voice в
`session.update` нельзя считать исправлением: документация разрешает этим событием
изменять настройки Responses delegation, но не аудиоконфигурацию. Пересоздание
сессии после согласия также добавит задержку и потеряет непрерывность контекста.

## Официальный контракт

[Managing GPT-Live sessions](https://developers.openai.com/api/docs/guides/live-conversations):
голос задается в `audio.output.voice` при старте; для его изменения нужна новая
сессия. Обновление Responses delegation сохраняет пропущенные настройки.
`session.updated` возвращает результирующую конфигурацию. Это описание контракта,
а не подтверждение фактического тембра конкретной аудиогенерации.
