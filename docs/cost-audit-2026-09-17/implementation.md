## Обновление после подключения OpenAI, 19:39 UTC

Пользователь настроил серверные переменные OpenAI. Синхронизация обоих провайдеров завершилась успешно: по 48 дневных снимков с 1 августа по 17 сентября. API перезапущен с новым окружением, `/health/ready` возвращает `ready`.

За 1–17 сентября OpenAI Costs API вернул **$5.224497** по выбранному проекту (17/17 дней). Локальная оценка сохранённого usage — **$2.441471**. Разница — **$2.783026**. Это успешное получение биллинга, но не совпадение локального учёта с провайдером. Twilio остался **$5.974220**, включая **$4.144600** за звонки.

Проверка по дням показывает крупнейшие расхождения 10 сентября ($1.770243, семь локальных операций без usage) и 15 сентября ($0.654387, две такие операции). За 1–4 сентября Costs API возвращает нули, поэтому отсутствие локальной истории до 5 сентября не объясняет сентябрьскую разницу. Всего остаются 15 платных операций без usage; для точного распределения расхождения нужны дополнительные провайдерские usage-данные. Дневные totals сами по себе не восстанавливают usage отдельных запросов.

Актуальные результаты: [дневная сверка](openai-reconciliation.json), [read model](implemented-data.json). Ниже сохранены результаты первоначальной реализации до подключения ключа. Упоминания отсутствующей конфигурации ниже относятся к тому этапу.

## Результат

Общая сводка, инспектор звонка и инспектор подготовки используют один компонент расходов: список категорий слева, детали справа, вкладки Cost / Usage / Requests. На узком экране детали переходят под список. Главные суммы округлены для чтения; внутри доступны шесть знаков, источники, версия тарифа и формула. Неизвестное значение отображается как «—», субцентовое — как «<$0.01», настоящий ноль — как «$0.00».

В beta-панели применяется тот же формат денег. Измеренные расходы, занятый бюджет и резервы подписаны отдельно. Период beta остаётся привязанным к резервированиям за последние 24 часа; это не месячный provider total.

Состояние базы проверено 2026-09-17 19:08 UTC:

| --- | ---: | --- |
| Twilio, весь аккаунт, 1–17 сентября | $5.974220 | Daily Usage API, получено 17 из 17 дней |
| В том числе локально учтённые звонки | $4.144600 | 13 цен Call Resource, дата начала операции |

Сумма Twilio состоит из звонков $4.144600, Media Streams $0.096800, SMS $0.380600, Verify $0.200000, номера $1.150000 и хранения $0.002220. Пересекающиеся родительские категории не суммируются. Это текущий Usage summary, не окончательный invoice. Последняя успешная синхронизация: 18:48:44 UTC; эта метка означает время получения ответа, а не внутреннее время обновления биллинга Twilio.

OpenAI пока **не сверён с Costs API**: в окружении нет `OPENAI_ADMIN_API_KEY` и `OPENAI_PROJECT_ID`. История локального usage начинается 5 сентября. Поэтому $2.441471 не объявляется полным расходом проекта и не складывается с Twilio в общее «итого». Скриншот с $7.62 за последние 30 дней не подменяет месячную сверку.

## Изменения учёта

- Локальные usage и charges попадают в период по `provider_operations.started_at`, с границами `[from, to)` в UTC. Поздний импорт июльских/августовских $9.01 больше не увеличивает сентябрь.
- Цена считается по каждой операции, затем агрегируется. Это согласует dashboard, request detail и beta. Разница с прежним расчётом OpenAI по общим корзинам составляет 73 микродоллара и объясняется округлением.
- Версия тарифа сохранена у usage. Неизвестная версия даёт неполный результат; обновление активной версии не должно молча переписывать старую стоимость. При добавлении тарифов необходимо сохранять поддержку прежних снимков в pricing policy.
- Проверяется наличие обязательных метрик у каждой операции, соотношение cached/input и token totals. Бесплатная moderation исключена из пропусков платного usage.
- Поздние duration/billable measurements добавляются в неизменяемый supplement ledger. View выбирает исходное значение или первое доступное дополнение. Replay не создаёт второй request и не изменяет исходную запись.
- Realtime response резервируется при начале. Поздний финальный usage, включая cancelled response, завершает ту же операцию. Незавершённые операции и прерванные сессии отражаются как неполнота. Это обнаружение пробелов, а не восстановление недоступных провайдерских событий.
- Twilio null/empty duration больше не превращается в ноль. Ожидание цены использует до 20 попыток: первые повторы через 15 минут, дальнейшие через 6 часов. Миграция переоткрывает только завершённые с `PROVIDER_CALL_COST_PENDING` задания.
- Импорт биллинга хранит append-only дневные снимки со scope и валютой. Публикация атомарная; advisory lock исключает конкурентные импорты. Отчёт использует последний снимок каждого дня. Пропущенные дни и давность более двух часов явно отражаются в статусе.
- Twilio total берётся из `totalprice`; детали выбраны без пересечений, остаток сохраняется как adjustments. OpenAI Costs запрашивается для конкретного проекта. Валюты не конвертируются автоматически.

## Эксплуатация

Миграция `0076_expense_accounting.sql` уже применена к локальной рабочей базе. Локальный API перезапущен; `/health/ready` возвращает `ready`. Во внешнем окружении перед запуском нового API нужно применить обычную миграцию проекта, затем развернуть API и web вместе. Публичный деплой в этой работе не выполнялся.

Синхронизация запускается на старте владельца background jobs и затем раз в час. Период загрузки — с начала предыдущего месяца по текущую дату UTC. Advisory lock защищает от одновременного выполнения API и worker. Ошибка одного провайдера не затирает последний успешный снимок другого.

Для ручной синхронизации из `apps/api`:

```powershell
node --use-system-ca --import tsx src/db/sync-provider-billing.ts --force
```

В собранном приложении: `node --use-system-ca dist/db/sync-provider-billing.js --force`.

Twilio использует имеющиеся `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN`. Для OpenAI нужны серверные `OPENAI_ADMIN_API_KEY` с доступом к Costs API и `OPENAI_PROJECT_ID` нужного проекта, после чего перезапуск API/worker и синхронизация. Секреты не передаются в web. Это подключение даст дневные денежные totals; отсутствующие исторические request-level usage оно не восстановит.

Сверка account billing доступна для календарных UTC-окон до 62 дней. Произвольное окно с началом внутри дня явно помечается как неподдерживаемое для дневных billing snapshots. Список запросов показывает последние 100 записей каждой категории и не является выгрузкой всего ledger. Неизвестные usage видны в общем счётчике пропусков.

Источники семантики: [Twilio Usage Records](https://www.twilio.com/docs/usage/api/usage-record), [Twilio Call Resource](https://www.twilio.com/docs/voice/api/call-resource), [OpenAI Organization Usage / Costs](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage). Проверка тарифов и ограничений источников сохранена в исходном аудите.

## Проверки и материалы

- Полный backend-прогон: 1 037 тестов в 99 файлах, 1 036 прошли сразу. Единственное старое ожидание даты импорта исправлено; повторный прогон соответствующего API, repository и aggregation набора — 49/49. Нерешённых тестовых ошибок в проверенной области нет.
- Новые проверки: границы UTC, исторический импорт, поздние immutable measurements, полнота usage, версия тарифа, rounding per operation, overlap категорий, provider scope/pagination, signed decimal amounts, Realtime replay/late usage.
- PostgreSQL-тесты выполнялись на новых изолированных базах. Существующая `TEST_DATABASE_URL` имеет старое расхождение checksum миграции 0065; эта база не изменялась. Для воспроизведения: `node --use-system-ca --import tsx scripts/test-isolated-db.mjs` из `apps/api`.
- Production build API, TypeScript API/web, ESLint изменённых компонентов и unit-тест общего форматирования денег прошли. Полная production-сборка Next в этой работе не запускалась.
- В браузере проверен настоящий общий компонент с минимизированными данными текущей базы: desktop, mobile, EN/DE, dark, call, empty, все категории/вкладки, раскрытия и возврат фокуса. Защищённая админка требует пользовательскую сессию; её авторизация не обходилась. Поэтому визуальная проверка проведена в отдельном loopback preview, а доступ к admin API покрыт backend-тестами.
