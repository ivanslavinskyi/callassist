# Подготовка плана: скорость и настоящий перевод

Локальный checkpoint 15.09.2026 после `5fee80c`. Связан с B09/B10/B12 из [текущего roadmap](mvp-plan.md). Это проверка подготовки и одобрения плана; телефонные звонки в этом прогоне не запускались.

**Последующее решение 15.09:** по запросу владельца `max_output_tokens` генератора
плана повышен с 5 000 до **20 000**, включая reasoning, для запаса на сложные
сценарии. Компактный вывод и обработка незавершённого ответа сохранены; это
верхняя граница одного ответа, а не целевой объём плана. Приведённые ниже
измерения относятся к прежнему пределу 5 000. Актуальный денежный расчёт и
резервы описаны в [отчёте о бюджете](budget-accounting-2026-09-15.md).

## Причины инцидента

Реальная подготовка завершилась за 155,54 с, хотя браузер прекращал опрос через 120 с. В PostgreSQL сохранены следующие длительности:

| Этап | Время |
| --- | ---: |
| Два запроса генерации, завершившиеся по тайм-ауту | 60,010 + 34,282 с |
| Ответ генерации, после которого потребовалась полная перегенерация | 40,898 с |
| Повторная генерация пригодного плана | 12,722 с |
| Две входные и одна выходная модерация | 2,293 с |
| Остальное, включая backoff фонового задания | 5,335 с |

Первый полученный ответ израсходовал весь лимит 5 000 выходных токенов, из них только 87 — reasoning. Следующий ответ использовал 580 токенов. Это указывает на чрезмерный или незавершённый вывод, а не на длительные рассуждения как единственную причину. Сырой исторический ответ не сохранялся, поэтому наличие именно повторяющихся пробелов в нём не доказано.

Отдельно локальный launcher передавал `TEXT_PROCESSOR_DRIVER=mock` при настоящем OpenAI-компиляторе. Поэтому перевод был сохранён как `ready` с генератором `text-processing-v2:mock`, а UI выводил `[MOCK ru: untranslated source]` как перевод. Строка с будущим условием успеха показывалась без отдельной подписи и могла восприниматься как фактический результат звонка.

## Изменения

- Сохранены `gpt-5.6` и reasoning `low`; включён `text.verbosity=low`, указан компактный JSON и объём плана, соответствующий заданию. Для одного простого вопроса не нужны дополнительные предположительные вопросы и длинные критерии. Пустой контекст не требует сгенерированного фонового описания.
- Незавершённый Responses envelope теперь отмечается как `invalid_response` с сохранением usage и не принимается даже при синтаксически корректном JSON. Единственный корректирующий повтор получает явную инструкцию вернуть завершённый компактный объект. Ограничения запросов, модерации, проверка фактов и полномочий записи сохранены.
- Создание, редактирование и уточнения используют общее ожидание до 8 минут с EN/DE статусами. Это резерв для восстановления после сбоев, а не целевая длительность нормальной подготовки. Опрос не создаёт новые операции.
- В локальных `.env` и сохранённых настройках launcher включён настоящий перевод. `/api/language-capabilities` подтверждает `processorMode=openai`, generation enabled, 24 направления для EN/DE/FR/IT/RU/UK и четырёх видов текста. Это локальная конфигурация; публичная языковая приёмка остаётся отдельной задачей. RM в текущем каталоге текстовых языков отсутствует.
- Смешанный запуск «настоящий компилятор + включённые mock-переводы» теперь отклоняется также при обычной локальной разработке. Полностью имитируемый режим и явно выключенная генерация остаются допустимы; изолированные автоматические тесты могут использовать fixtures.
- UI не проецирует сохранённый mock как перевод, позволяет запросить настоящий перевод старой заглушки и предпочитает реальную генерацию. Сервер с реальным переводчиком отклоняет одобрение, основанное на mock-артефакте. Уже сохранённый исходный план не переписывается.
- Критерии успеха подписаны `Expected result` / `Erwartetes Ergebnis`.

Настройка компактного вывода соответствует [рекомендациям OpenAI по задержкам](https://developers.openai.com/api/docs/guides/latency-optimization); параметры модели сверены с [документацией GPT-5.6](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6).

## Реальные измерения

Все задания вымышленные, модель та же, в каждом случае одна попытка worker / одна генерация. В первых трёх пробах проверялась компактная конфигурация; четвёртая прошла через исправленный CallService, durable workers, определение языка, перевод и одобрение по хешу артефакта. Тестовые планы хранились в памяти, дневные резервы расходов — в основной локальной БД.

| Сценарий | План с проверками | План и настоящий перевод |
| --- | ---: | ---: |
| Один бытовой вопрос, RU → DE | 7,75 с | — |
| Документы для регистрации и подача онлайн | 10,24 с | — |
| Запись на консультацию на следующей неделе, 14:00–16:00, без оплаты | 17,70 с | — |
| Повторный бытовой пример через весь сервис, RU → DE → RU | 9,28 с | 14,19 с |

Все планы прошли политику с первой генерации. В сценарии записи сервер вывел семь разрешённых дат следующей календарной недели и сохранил время, максимум одной встречи и запрет новых финансовых условий. В последнем прогоне 11 полей переведены на русский без mock-маркеров; по готовому переводу успешно одобрен исходный план. Проверка не запускала звонок.

Проверки: **281 тест API** в затронутых наборах (компилятор, scheduling, политика, тайм-ауты, текстовые артефакты, конфигурация и CallService), **77 тестов web**, typecheck API/web, web lint. Проверены в том числе неполный envelope, отказ от mock-одобрения, сохранение черновика, восстановление на второй/третьей попытке, неизменность полномочий при переводе и защита от повторных операций. API readiness и публичные capabilities возвращают 200.

## Границы и остаток

- Четыре живые пробы подтверждают улучшение, но не дают p95 или гарантии задержки под нагрузкой. B09 остаётся местом приёмки языков, ошибок провайдера и конкурентных запросов во внешнем окружении.
- Сохраняется утверждённый бюджет **20 USD за скользящие 24 часа**. Пробы использовали его консервативные резервы; это не фактический счёт провайдера. После проверок зарезервировано **12,50 USD**, осталось **7,50 USD**. Один звонок с пределом 7 минут требует резерва 14 USD при текущих ставках и сейчас не пройдёт допуск. Тестовые резервы не удалялись и бюджет не увеличивался.
- Отдельный скрипт перевода сохранённого пользовательского плана остановила автоматическая проверка разрешений из-за передачи текста и имён OpenAI; скрипт не выполнялся. Пока шли проверки, приложение само отправило запрос через открытый UI: POST `/api/call-briefs/:id/plan-review` принят в 11:07:46 UTC, настоящий артефакт готов в 11:07:52 UTC. Итоговая read-only проверка: 15 полей, `text-processing-v2:openai:gpt-5.6`, без mock-маркеров, тот же хеш исходного плана. Повторная отправка и отдельное разрешение для уже выполненного перевода больше не нужны.
- Переключение `.env` само по себе не переписывает старые артефакты. Старый mock можно заменить настоящей генерацией; исходный план, его хеш и полномочия сохраняются.
